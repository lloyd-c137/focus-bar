# 01 · 产品需求文档（PRD）

版本：V1.0 · 2026-11-22 · 状态：产品方案，尚未实现

## 1. 一句话定义

Focus Bar 是运行于 macOS 菜单栏中的每日智能事项清单。用户在完成一次性设置后，系统每天基于长期目标、可信的截止事项、当前日程、项目进度及历史任务自动生成和维护一张可以直接执行的清单。

**核心用户旅程：点击菜单栏图标 → 看到今天需要处理的事项 → 勾选完成或做极少量修改 → 关闭面板。**

不做计时器；不做“Start Focus”；不要求用户每天填写今日计划。视觉及交互必须符合 macOS 原生美学。

## 2. 问题与目标

### 当前痛点
- 长期目标与当前待办存在于不同地方，用户需要每天重新决定先做什么。
- 截止日期、会议、GitHub 工作进度、学校任务互相割裂。
- 传统待办软件需要手动录入和维护；自动汇总全部 Issue 又会制造噪音。
- 看清单本身不应该变成复杂工作，菜单栏应当是最低摩擦的入口。

### 产品目标
1. **零日常录入**：在有可用数据来源时每天自动生成清单，通常无需手动制定。
2. **可信**：每件自动事项可追溯到数据来源或明确的 AI 建议，不虚构截止日期、承诺和完成状态。
3. **可控**：勾选、推迟、删除、固定、编辑后不被自动刷新推翻。
4. **低打扰**：除用户主动打开外，默认不频繁弹窗或发通知。
5. **极简原生**：一个菜单栏弹出面板解决 90% 的日常操作，设置使用独立原生窗口。

### 非目标
计时器、番茄钟、聚焦时长统计、桌宠、全屏 Dashboard、移动端、跨设备账户、多人协作、邮件自动发送、自动修改外部 Issue/日历、自动执行代码或其他高风险操作。

## 3. V1 用户与场景

首要用户同时兼顾学业、多个长期项目和组织事务，需要把任务集合成一张当日清单。数据来源示例包括：学校作业的用户记录、GitHub 中的选定仓库、macOS 日历、手动捕获的临时事项、长期固定的每日习惯。

典型需求：
- 早上第一次打开 Mac，无需输入就看到今天的事情。
- 课程/会议已经占用大量时间时，自动减少“建议今天做”的工作，不遗漏必须处理的截止任务。
- 临时想到待办，快速记录即可，默认不会立即重排今日计划。
- 一个项目连续几天没有完成，系统能延续计划，但不会无限重复推送。
- 外部数据断连时，昨日已经确认的事项与本地任务仍可查看。

## 4. 信息架构

**菜单栏常驻：** 单色符号为默认样式，完成进度为可选显示项。正常状态不显示通知角标。

**今日面板（Today）：**
- Header：Today、系统本地日期、溢出菜单。
- 摘要：剩余事项数 / 已完成数，可选择隐藏。
- 分组任务：Must Do（必须处理）、Priorities（建议重点推进）、Routine（日常习惯）。分组中没有任务则不展示空标题。
- Task Row：复选框 + 标题；必要时一行简洁副标题，显示来源或明确截止时间。
- Footer：内联 Add、手动 Refresh、Settings、最后更新时间/数据状态（必要时）。
- 任务较多时在面板内部滚动，避免超出屏幕高度。
- 已完成任务默认为折叠至 Completed 区域，可在设置中选择不折叠。

**辅助入口：** Quick Capture 快捷键、小型原生 Settings 窗口；不做完整任务管理主窗口。

## 5. 功能需求

| ID | 需求 | V1 验收重点 |
| --- | --- | --- |
| FR-01 | 系统菜单栏常驻，点击展开/关闭 | 登录后可启动；关闭面板不退出 |
| FR-02 | 完整展示每日事项，数量不设上限 | 长清单内部滚动，可读可操作 |
| FR-03 | 自动生成当日清单 | 首次当日运行或指定时刻生成；本地缓存 |
| FR-04 | 确定性规则 + 可选 AI 推荐 | 结构化解释，绝不将建议伪装成事实 |
| FR-05 | 分组、排序和折叠 | Must Do / Priorities / Routine |
| FR-06 | 完成、撤销完成、编辑、推迟、删除 | 本地立即保存；覆盖操作有优先权 |
| FR-07 | Quick Capture / 内联添加 | 不要求预填类别；保留原文 |
| FR-08 | 长期目标及重复习惯配置 | 一次性设置，可在 Settings 调整 |
| FR-09 | GitHub 选定仓库只读同步 | 选择项目、限制范围、断连可降级 |
| FR-10 | 本地 EventKit 日历读取 | 授权后只使用选中的日历 |
| FR-11 | 历史计划与日界线处理 | 同一天多次启动不重置；次日生成新快照 |
| FR-12 | 来源与推荐理由 | 任务详情可看来源、建议依据和更新时间 |
| FR-13 | 离线回退和同步错误 | 有缓存可用，不伪造“最新”状态 |
| FR-14 | 隐私、安全、无障碍 | Keychain、最小授权、VoiceOver、键盘支持 |

### 任务操作语义
- 勾选完成仅更新 Focus Bar 的任务状态，不自动修改 GitHub、Calendar 或外部数据。
- 右键菜单：编辑、推迟至明天/选日期、置顶/取消置顶、从今日移除、查看来源。删除必须区分“从今日移除”与“彻底删除本地录入事项”。
- 对来自外部日程的事件，**默认作为日程约束/提醒信息**，不擅自转化为可勾选任务；若可明确识别行动项才生成关联的建议任务。
- 系统不应因任务数量超过 3 而裁剪必须完成的事项。

## 6. 生成与更新原则

- 每日生成使用系统本地时区的日历日，不以 UTC 直接分日。
- 每天的计划是稳定快照；刷新时合并新事实，而不是覆盖全表。
- 有证据支持的明确截止事项可以列为 Must Do；推断的“应该推进”只能列为 Priorities/建议。
- 优先满足约束：用户固定/编辑过的事项 > 明确截止与已承诺事项 > 优先级评分 > AI 表述优化。
- 不自动完成任务，不因 GitHub PR 合并直接判定个人工作全部完成。
- 可选择不启用 AI；本地规则仍能生成基础清单。
- 没有足够数据时显示解释性空状态和接入/添加入口，不能生成虚构任务凑数。

## 7. 首次引导（约 1–3 分钟目标）

1. 欢迎页：说明只在菜单栏运行、默认本地存储。
2. 用户可输入 1–5 个长期目标及排序（允许跳过），定义固定日常习惯（允许跳过）。
3. 自愿连接 Calendar、选定 GitHub 仓库；拒绝不影响应用基本运行。
4. 自愿配置 AI 提供方与 API Key，清楚展示何时向云端发送什么。
5. 首次生成；若资料不足，展示真实空状态。
6. 设置可以稍后修改，不允许因未连接第三方而卡死。

## 8. 成功指标（提议的目标，不是现有数据）

- 7 天真实使用中，每日手动维护中位数 ≤ 1 分钟（不含一次性设置）。
- ≥ 80% 的系统推荐事项被评价为“确实值得今天处理”。
- 0 个被证明是模型编造的真实 Deadline 或用户承诺。
- 关键状态丢失/被自动重排覆盖：0 次。
- 断网/权限拒绝时基础清单仍然可用。
- 系统启动无主窗口，面板打开的主观体验接近原生菜单栏应用。

## 9. 实现前明确假设

- 用户拥有可安装原生 macOS 应用的 Mac。系统最低版本暂定 macOS 14，必须在真实机器上验证。
- V1 面向个人本地使用；首版不设计云同步与团队协作。
- GitHub 活动只提供候选与进度线索，不能直接等同个人任务。
- 若学校任务无受支持的数据连接，用户通过 Quick Capture 或日历/提醒事项录入，不能声称能够自动读取学校平台。
