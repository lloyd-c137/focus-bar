# 06 · 隐私、安全与可靠性方案

**核心立场：** Focus Bar 面向学业、个人安排和可能涉及私有仓库的工作。默认本地处理与最小权限优于“为了 AI 更聪明而收集一切”。

## 1. 数据分类

| 分类 | 例子 | 处理策略 |
| --- | --- | --- |
| Local task data | 用户任务、目标、历史完成记录 | 本地数据库；允许删除/导出 |
| Calendar metadata | 选定日历中的标题/时间/地点（若必要） | 最小采集；默认只读；限制保存范围 |
| GitHub metadata | 选定仓库的 Issue/PR 标题、状态、URL | 只读；尽量使用摘要、来源标识 |
| Secrets | GitHub Token、LLM API Key | 仅 Keychain；永不写日志或存 Git |
| AI Context | 提交给模型的候选行动摘要 | 明示授权、最小化、可预览/关闭 |
| Diagnostic data | 类型、耗时、失败码 | 默认本地；避免保存敏感正文 |

## 2. 权限与信任边界

- Calendar：用户明确授予读取所需的系统访问权限（EventKit 的 full access 请求），应用代码严格不做写操作；用户进一步选择哪些日历纳入。
- GitHub：仅选定仓库；使用 fine-grained 凭证限制 read 权限；Keychain 存储；授权过期可重新配置。
- LLM：与 GitHub、Calendar 分开授权。禁止“连接日历”自动等价“允许把日历内容上传到模型”。
- Clipboard/Screen/Accessibility：V1 **不申请** 屏幕录制、辅助功能监控、输入监听等与本产品无关权限。
- Notifications：V1 默认不主动推送，未来若增加必须单独征求权限。

## 3. AI 发送边界

用户启用云端模型前，必须看到：
- 提供方和模型信息。
- 会发送哪些字段，例如任务候选的标题、简短摘要、日期与目标匹配度。
- 敏感字段不默认发送：私有仓库源码全文、日历完整描述、参与者邮箱/联系人、会议地址、访问令牌。
- 用户可以选择不发送特定目标、仓库、日历，或关闭 AI 全部使用规则模式。
- 模型提供方自己的数据政策应直接链接，不能由应用替其承诺零留存。

建议先本地进行数据归一化和去标识化，给 LLM 传`candidate_id` + 经过允许的摘要，结果返回后在本地映射 ID，并在写入之前校验。

## 4. 提示注入与结构安全
- Issue、PR、日历文本、用户捕获内容均为不受信任数据，不能在提示词中晋升为系统规则。
- 规划模型不能调用外部执行工具；它只输出结构化建议，不持有 GitHub / Calendar Token。
- JSON 解析严格校验 schema、候选 ID、来源、枚举、长度、可接受任务数量、排序和字段范围。
- 不允许模型赋予事实型截止日期、不允许自动新建有外部副作用的事件/Issue。
- 渲染层将外部文本作为纯文本，不解释任意 HTML 或执行 shell/代码。
- 外链打开需限定 HTTPS 等安全协议，避免恶意 sourceURL。

## 5. 密钥、日志和文件
- Token 与 API Key 写 Keychain（按服务命名和适当 access control）；不得出现在 UserDefaults、SwiftData、日志、Crash report 的可读字段。
- 网络请求日志屏蔽 Authorization、Cookie 和请求正文中的隐私字段。
- 本地数据库文件依赖系统用户访问控制；在可行时启用适当的数据保护/备份策略。
- Export 只由用户主动触发，明确告知含私人数据。Import 应校验 schema、防止破坏本地状态。
- 不把私人真实数据加入测试 fixture 和 GitHub 仓库。
- 选择性删除缓存，撤销来源后允许用户删除该来源本地快照及衍生候选。

## 6. 用户数据控制

设置中应支持：
- 查看连接状态和最后同步时间。
- 逐个断开 GitHub/日历/AI。
- 删除某来源的缓存/衍生建议。
- 清空本地历史及全部用户数据（需确认）。
- 输出诊断摘要（默认脱敏）以便调试。
- 不提供含糊的“我们永远不会处理你的数据”保证；说明访问边界和外发时机。

## 7. 可靠性与恢复
- 数据库写操作采用事务语义，Task 与 DailyPlanItem 一致更新。
- 用户勾选后不依赖网络结果确认是否成功，本地保存失败时撤销 UI 乐观状态并提示。
- 外部同步错误不能清空正常列表。
- AI 返回不符合 schema 时回退规则引擎，不插入部分无效结果。
- 单次刷新/重试有次数和超时上限，避免高频 API 账单和菜单栏 CPU 占用。
- Mac 断网、睡眠、重启时必须从本地数据库恢复最后可用快照。

## 8. 发布前安全测试
- Token 从不出现在 Github commit、截图、诊断、应用错误弹窗或本地日志。
- 权限被拒绝/撤销/过期后行为正常，且断连不会触发无限授权弹窗。
- 恶意 GitHub Issue 文本试图命令 LLM 忽略用户规则时，依旧只能作为候选数据。
- 不包含任何无需许可的网络监听、屏幕监控或后台键盘监听。
- 对外发送模型数据时采用用户授权的来源白名单，严禁越权字段。
- 公开仓库中必须只使用虚构 fixture；任何真实私有数据泄露视为阻断发布缺陷。
