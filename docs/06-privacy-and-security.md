# 06 · Focus Bar V1 隐私、安全与可靠性

状态：设计 / 未实现

## 1. 隐私边界

V1 **纯本地应用**。用户手动输入标题、日期、可选时间、备注与重复规则；数据仅存储于本机应用数据目录。

**V1 不存在以下行为：**
- 调用 LLM / AI 模型，或发送任何任务信息给云服务。
- 使用 GitHub、Calendar、Reminders、邮件或通讯录连接器。
- 自动分析屏幕内容、全局键盘输入、浏览器页面或其他应用窗口。
- 使用用户账号、远程数据库、远程 telemetry 或后台同步服务。

因此不应请求 GitHub Token、AI API Key、Calendar 权限、屏幕录制、Accessibility/输入监控、麦克风或定位权限。快捷键若采用系统热键方式，需要说明并确保不使用键盘监听/记录。

## 2. 本地数据

| 类型 | 保存内容 | 访问策略 |
| --- | --- | --- |
| Task | 标题、备注、计划日期/时间、完成状态 | 应用私有 SwiftData Store |
| RecurrenceRule | 频率、开始日期、结束规则、星期字段 | 应用私有存储 |
| OccurrenceOverride | 特定日期的完成/跳过/编辑例外 | 应用私有存储 |
| Preferences | 菜单栏计数、登录启动、显示偏好 | 本地设置 |
| Diagnostics | 必要的错误类型、版本、时序 | 默认仅本地且脱敏 |

任务标题和备注可能包含敏感信息。日志不得记录用户完整任务文本或数据库内容。无需 Keychain 存放 API 密钥，因为本版根本没有外部凭证。

## 3. 数据可靠性

- CRUD 操作应在事务语义下写入；失败时显示错误，不允许 UI 误报保存成功。
- 显式区分完成、改期与删除，避免误操作造成日程丢失。
- 删除可以使用确认或可撤销的软删除机制，并测试恢复。
- 数据库迁移失败时禁止静默清空数据库；尽可能保留原始数据并提供恢复提示。
- 跨时区时不改变用户选定的日历日。
- 用户可离线完整使用，网络中断不产生异常状态。
- 开发期间不向公开仓库提交真实用户数据库或个人任务样本。

## 4. 导入与导出

V1 不要求导入导出功能。如果以后提供，必须用户显式触发，使用本地文件选择器，并在导出时提醒文件包含个人数据；不得自动上传云端。

## 5. 发布与构建

- 公开仓库仅包含源代码、假数据与文档。
- 发行前检查 App Sandbox、应用容器位置、登录启动与签名/公证行为。
- 不添加不必要的 Network/Calendar/Screen Recording entitlement。
- 若自动更新依赖网络，需单独评审用户授权、隐私声明及实现；V1 不预置自动更新联网功能。

## 6. 最小安全验收

- [ ] 在无网络的 Mac 上，新增、编辑、完成、日期切换、重复规则均可正常运行。
- [ ] 系统隐私权限列表不出现 Focus Bar 无关的访问请求。
- [ ] SQLite/SwiftData 数据故障不会静默清空所有任务。
- [ ] 日志和 UI 截图 fixture 无真实私人事项。
- [ ] 任务保存失败时有可理解的错误提示。
- [ ] Settings 能管理登录启动和本地用户偏好，不出现外部授权设置。

本阶段目标是**安全、安静、完全本地**，不是搭建未来 AI 系统的空壳。
