# 08 · 用户流程与边界场景

Focus Bar 是长期待办清单。事项没有计划日期；用户可按需设置截止日期、时刻和重复规则。

## 1. 第一次打开

1. 启动后菜单栏出现 Focus Bar 图标。
2. 点击后打开 `Tasks` 长期清单。
3. 空清单显示 `No tasks yet. Add one below.`。
4. 用户输入标题并按 Return，任务保存并一直保留。
5. 手动管理事项无需注册或接入日历/AI；如需自动备份，用户需配置仅访问私有备份仓库的 GitHub token。

SwiftData 初始化失败时显示存储错误，不将读取失败伪装成空清单。

## 2. 创建长期事项

1. 在底部输入标题并按 Return。
2. 不设置截止日期时，任务不会因日期流逝变成 Overdue。
3. 用户可为事项设置可选时刻；它是时刻标签，不附着某一天，也不发送提醒。
4. 事项直到完成或删除前持续显示。

## 3. 设置截止日期

1. 新建时打开日历按钮，或在事项详情中打开 Deadline。
2. 选择截止日期并保存；可随时编辑或清除。
3. DDL 未来时事项正常显示；DDL 过去且未完成时进入 Overdue。
4. 完成的事项进入 Completed，不会继续显示为 Overdue。

## 4. 完成与撤销

1. 点击复选框，数据库提交后任务进入 Completed。
2. 展开 Completed 可撤销完成。
3. 重启应用后状态保持。

保存失败不能显示永久完成状态，不能把完成解释为删除。

## 5. 每日/每周重复

1. 添加事项并选择 Daily 或 Weekly。
2. Weekly 明确选择星期；默认使用创建当天的星期。
3. 完成本次 occurrence 不影响后续实例。
4. 删除重复任务时可选择仅本次或整个系列。

不累积很久以前漏做的 occurrence。截止日期只影响被设置的当前 occurrence。

## 6. 大量事项与异常

- 0 项：空状态和底部新增输入框。
- 20–50 项：列表滚动，新增入口保持可访问。
- 长中文标题：最多两行，详情可查看并编辑全文。
- 12/24 小时显示遵循系统 Locale。
- 离线时核心操作照常。
- 修改成功后后台触发 GitHub 备份；断网时待本地网络恢复后重试，备份失败不会回滚任务操作。
- 输入法组合态按 Return 只确认候选文字。
- 数据库写入失败时保留草稿并提示错误。
- 删除可撤销；连续快速勾选保持最终状态准确。
- VoiceOver 正确读取标题、DDL、重复与完成状态。

## 7. 用户可见文字

- Tasks / 事项
- Overdue / 已逾期
- Anytime / 不限时间
- Completed / 已完成
- Deadline / 截止日期
- Add a task / 添加事项
- No tasks yet. Add one below. / 还没有事项，在下方添加一条。
- Unable to save. Try again. / 保存失败，请重试
