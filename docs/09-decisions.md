# 09 · 决策记录（ADR Lite）

本文件为后续开发的产品范围基准。任何会改变用户已确认需求的决定都必须追加新记录，不能静默恢复过时方案。

## ADR-001 · 命名为 Focus Bar

**状态：已确定。** 品牌正式名称：**Focus Bar**；文字标识可用小写 `focus bar`。不要继续使用 Focus OS 作为产品名或 Bundle Display Name。

## ADR-002 · 仅做原生 macOS 菜单栏

**状态：已确定。** 首版仅 macOS 菜单栏应用。默认不显示 Dock 主窗口；通过菜单栏展开清单，设置可独立打开。架构使用 Swift/SwiftUI 与必要 AppKit，不采用 Electron/WebView 作为主 UI。

## ADR-003 · 极简高级感，遵循 macOS 设计美学

**状态：已确定。** 使用系统字体、SF Symbols、原生系统色/材质、自然留白与精确对齐。支持 Light/Dark、键盘和 VoiceOver。不要为了高端感添加渐变、厚重阴影、套娃卡片或复杂动效。

## ADR-004 · 只做每日事项清单

**状态：已由 ADR-010 更新。** 面板显示长期事项清单，不按计划日期过滤。仍不做 Start Focus、计时器、番茄钟、桌宠和专注时长统计。

## ADR-005 · V1 手动录入，不接入 AI

**状态：已确定（2026-11-22）。** 用户手动输入标题、可选 DDL、时刻、备注与重复规则。此前 AI 自动规划、GitHub 和 Calendar 数据接入的方案**不属于当前实施范围**。

## ADR-006 · 默认本地与离线

**状态：已确定。** 不设置账号、不使用服务器、外部同步或模型服务。所有核心功能离线可用，SwiftData 保存本地事项。应用不得申请与 V1 无关的隐私权限。

## ADR-007 · 日期与时间

**状态：已被 ADR-010 取代。** 日期导航和计划日期已移除。

## ADR-008 · 迭代顺序

**状态：已确定方向。** 先保证菜单栏外观与手动任务闭环，再做日期/重复/逾期与可靠性。任何 AI 或外部集成都要新的明确授权、设计和验收，不能偷偷复活。

## ADR-009 · 可选截止日期

**状态：部分更新于 ADR-010。** 事项默认无 DDL，可在新增或编辑时按需设置。DDL 是唯一触发 Overdue 的日期；重复事项的 DDL 只作用于当前 occurrence。

## ADR-010 · 删除计划日期（2026-11-25）

**状态：已确定。** 用户明确要求删除计划日期机制。事项不再有计划日期字段、日期导航、Move to Today/Tomorrow 或按日期筛选。普通事项长期留在清单中，直到完成或删除；没有 DDL 的任务不会自动逾期。只有用户显式设置且已过去的 DDL 才会将未完成事项归入 Overdue。

时间字段仍可选，但只是时刻标签，不附着到某个日期。Daily/Weekly 规则用频率和星期生成 occurrence，完成状态按实例独立。

为打开既有 SwiftData Store，旧 `dayKey` / `rescheduledDayKey` 存储列暂时保留；不得将其用于可见行为。现有事项的标题、备注、DDL、时刻、重复与完成状态必须保留。

## 仍需真实验证的技术细节

- 最低支持的 macOS 版本、SwiftUI MenuBarExtra window + Settings 的实际兼容性。
- Agent app / LSUIElement 与登录启动的组合表现。
- SwiftData 日期字段、迁移与重复规则的持久化策略。
- 删除使用 Undo 还是二次确认的最佳原生交互。
- 首次登录是否提示设置开机启动（默认不强制）。
- 全局快捷键是否有必要：V1 可仅通过菜单栏添加，避免不必要复杂度。

以上是工程验证项，**不是向用户重新确认已明确的产品需求**。
